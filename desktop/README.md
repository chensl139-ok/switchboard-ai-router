# macOS 桌面 App

桌面版使用原生 AppKit / WKWebView 窗口，内置 Node 和生产依赖。安装使用时不需要 Docker、Node、npm 或终端。当前可在 Apple Silicon Mac 上构建和使用，最低系统为 macOS 13。

## 安装与使用

打开生成的 `Switchboard-<版本>-macOS-arm64.dmg`，将 `Switchboard.app` 拖到“应用程序”，随后双击打开。

首次启动会自动创建本机配置。填写姓名、邮箱和至少 12 位密码，创建管理员账户；初始化令牌由桌面 App 安全地传给本机页面，无需手动编辑 `.env`。之后直接使用平台页面配置服务商和模型。

顶部显示当前 API 地址，默认 `http://127.0.0.1:3110/v1`。端口占用时会自动分配另一可用端口，以界面显示为准。服务仅绑定本机，其他电脑无法通过此地址访问。关闭窗口后 App 继续运行；按 `⌘Q` 退出会停止本机 API 服务。

“导入已有部署…”可选择包含 `.env` 与 `data/` 的项目目录。导入创建独立副本，保留原部署和前一个桌面配置。SQLite 使用备份接口复制，旧登录会话不会迁移。建议先停止原服务以保证多个数据文件的一致性。导入失败时原桌面配置仍保留；从菜单重启可恢复。

数据位于 `~/Library/Application Support/Switchboard/profiles/`，通过菜单“打开数据目录”访问。升级只替换 `.app`，不要删除此目录。备份时应退出 App，并保存整个 `Switchboard` 数据目录，包括 `.env`、`master.key` 及所有租户数据。

导入已有飞书企业配置后，可直接在 App 中点击“使用飞书登录”，选择对应企业。App 使用 macOS 系统认证会话打开浏览器授权，登录成功后自动回到工作空间；企业身份连接也使用这一流程。是否直接使用已有飞书会话、需要扫码或唤起飞书客户端，由飞书授权页决定，App 不会跳过用户授权。

每个已绑定企业的飞书应用都需要在“安全设置 → 重定向 URL”**新增** `http://127.0.0.1:3110/api/account/sso/feishu/callback`，保留原部署的回调。App 不覆盖导入的 `.env` 或企业绑定配置。端口占用时仍可使用邮箱登录；若要使用飞书，应释放 3110 后重启 App，或登记实际端口的回调。菜单“飞书登录配置说明”可复制当前回调地址。首次登记后可能需要企业管理员发布/审批应用。

浏览器只取得短时、一次性授权票据；登录会话不放在 URL 中。授权结果仅可由发起登录的本机 App 兑换，并在兑换后立即失效；取消、超时和退出均清理未完成的登录结果。完整登录由本人在飞书授权页完成。

## 开发与打包

需要 macOS、Xcode Command Line Tools、符合项目要求的官方独立 Node 二进制以及 npm 开发依赖：

```sh
npm ci
npm run build:desktop
```

产物在 `dist/desktop/`：App、DMG、SHA256SUMS。打包脚本会校验运行时架构和动态库依赖，执行前端生产构建，只复制程序与生产依赖。`.env`、`data/`、测试及本地账号密钥不包含在安装包中。Node 与依赖的许可证随 App 保存。

默认使用构建时的 `process.execPath`；可通过 `SWITCHBOARD_NODE_BINARY` 指定同架构的官方 Node。原生窗口与运行时必须是同一架构。Intel 包需在对应环境构建并验收；当前交付不含 Windows 安装程序。

当前产物使用本地 ad-hoc 签名，适用于本机安装；没有 Apple Developer ID 签名和公证。向其他电脑正式分发前，应配置开发者签名、加固运行时和公证流水线。不要以关闭系统安全检查作为安装步骤。
