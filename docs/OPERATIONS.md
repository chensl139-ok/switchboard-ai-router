# 升级与实例核对

## 先明确实例

浏览器地址决定连接哪个服务。Docker 默认 `127.0.0.1:3100`；桌面 App 通常使用 `127.0.0.1:3110`，被占用时可能改用随机端口，以 App 菜单为准。公网地址可能转发至另一台机器，更新本机不会自动更新公网。

两种部署使用同一套核心代码，数据独立保存：Docker 默认挂载仓库的 `data/`，配置来自仓库 `.env`；macOS App 使用 `~/Library/Application Support/Switchboard/` 中的配置档案和数据。

不要同时运行多个进程读写同一数据目录。迁移前停止源和目标服务、完整备份，再按原有结构迁移；不能只复制 SQLite 主文件或漏掉 `master.key`。

## 判断是否同一版本

在「账户与租户 → 版本与运行环境」查看版本号与构建指纹，或从源码目录运行：

```sh
npm run doctor -- --url http://127.0.0.1:3100 --url http://127.0.0.1:3110
```

工具只读 `/readyz` 与 `/api/account/status`，无需密钥，不产生模型调用。全部实例就绪且版本、指纹相同时返回 `consistent: true` 和退出码 0；不一致、旧版无指纹或连接失败返回非零。

指纹比较核心程序与发布的网页资源，不包含用户数据、凭证、原生外壳或构建时间。相同指纹不代表租户数据同步，也不代表网页拥有桌面专属的个人订阅连接能力。

## Docker 升级顺序

1. 检查本地修改与目标提交，先构建新镜像或拉取明确的镜像 digest。
2. 停止 Switchboard 容器，备份 `.env` 和完整 `data/` 到仅自己可读的目录。
3. 用新镜像重新创建容器，保留数据挂载和原有令牌。不要使用 `docker compose down -v` 清理数据。
4. 检查容器健康，再运行 doctor，登录验证当前租户、模型目录和实验历史。
5. 回退时停止新容器、恢复完整备份，再启动对应旧镜像；不要让旧代码直接打开已迁移的数据结构。

`latest` 是正式发行版；`main` 是另行发布的主分支镜像。更新源码、镜像和桌面 App 是不同步骤，不能仅凭版本号判断更新结果。

## 桌面升级

退出 App 后备份完整应用支持目录，再替换 `/Applications/Switchboard.app`。安装包不含用户数据，替换程序不会删除账号、密钥和历史。确认新 App 正常后清理其他位置的重复 `.app`，保留需要分享的安装包即可。
